# Widscan58 风险登记册（RF Track 阶段 0）

> 审计日期：2026-10-28。风险等级 = 可能性 × 影响（高/中/低）。标注：**[已由源码确认]** / **[根据源码推断]** / **[需要实机验证]**。

## R1. 频道扩容触碰固件硬限制
- 事实：`PROFILE_MAX_CHANNELS 8`（profile.h:8）遍布 scanner/planner/rh；ENABLE 掩码 u32（commands.c:408）构成隐藏 32 频道上限，第 33 频道静默失效。**[已由源码确认]**
- 影响：高。40+ 频道目标必须改固件结构体、命令解析与 web 侧 `1 << id`（channelPlan、device.ts）。
- 缓解：分阶段方案见 `docs/rf-track/channel-limit-audit.md`；ENABLE 位集改造为独立固件分支。

## R2. 无状态库/无组件边界的演进风险
- 事实：web 无框架，视图直接操作 DOM 与 App 单例；canvas 手绘。**[已由源码确认]**
- 影响：中。工作台组件化若照搬框架思路会大改；若照搬现有"单视图"模式会互相耦合。
- 缓解：`web-extension-boundaries.md` 已给出最小侵入集成边界（独立挂载点 + Store 订阅 + Transport 适配器）。

## R3. 并行会话与工作区卫生
- 事实：审计时工作区有 5 个已修改业务文件与 4 个未跟踪文档（属并行工作流）。**[已由源码确认]**
- 影响：中。提交混杂、覆盖他人半成品。
- 缓解：提交前逐文件核对 `git status`；他人半成品只 unstage 不删（项目既定约定）。

## R4. 数据真实性失守
- 事实：项目已有 mock 目录；SPECTRUM 帧为真实频率轴但跳频采样；无测向/定位能力。**[已由源码确认]**
- 影响：高（产品信誉）。演示动画若不标 DEMO、离散 RSSI 若冒充连续频谱即违反约束。
- 缓解：所有模拟源强制 `MOCK/DEMO` 状态字段；不支持能力显示 `unsupported`；已写入各实施文档验收标准。

## R5. 逆向 I/Q 机制的稳定性
- 事实：RAW IQ 依赖 SRAM 银行 0x40830000 直读（radio_c5.c:28-37），非官方公开接口；有 FILL/GUARD 字校验与重校准表。**[已由源码确认]**
- 影响：中。芯片 SDK 升级可能使地址/行为失效。
- 缓解：守卫字校验已在固件内；升级 IDF 时专项回归 RAWIQ **[需要实机验证]**。

## R6. 串口独占与多消费者冲突
- 事实：USB CDC 单流；文本命令与二进制帧复用同一流；本机曾发生浏览器占用串口导致命令行无法访问。**[已由源码确认]**
- 影响：中。网关/多组件同时取数会争用。
- 缓解：网关侧单点持有串口并向多客户端分发（serial_bridge.py 模式）。

## R7. 测试缺口
- 事实：CI（pages.yml）只构建发布，不跑测试；固件真机回归无自动化。**[已由源码确认]**
- 影响：中。RF Track 每阶段依赖人工执行 `npm test`/e2e/`pio test -e native`。
- 缓解：以 M0 基线为回归门槛（56/56 + 28/28 + 17/17），纳入每阶段报告。

## R8. 许可证
- 事实：项目 GPL-3.0-or-later；运行时依赖 esptool-js Apache-2.0、spark-md5 WTFPL/MIT、serialport MIT；固件组件 esp-dsp（Apache-2.0 系，依 Espressif 组件惯例）。**[已由源码确认（依赖 license 字段）；esp-dsp 许可证细节需复核上游]** 
- 影响：低-中。GPL 对闭源商业化插件/云端分发有传染约束。
- 缓解：第一版不做第三方插件动态加载（计划已定）；商业化前做专项法律核查。**[当前无法确认，留待法律核实]**

## R9. 多节点带宽与队列
- 事实：RAW IQ 单快照 16380 字 ×4 字节、SPECTRUM/LEVELS 帧 100ms 级；link.c 环形缓冲 16KB 有界。**[已由源码确认]**
- 影响：中。网关聚合多节点时链路饱和、丢帧。
- 缓解：有界队列 + 背压策略写入插件运行时验收标准；网关带宽实测列入阶段 7。**[未执行]**

## R10. 大模型接入引入的新风险
- 事实：方案新增模型网关与 `llm-analyst` 编排插件（`docs/architecture/llm-integration.md`）；默认 `enabled=false`，调用走单一出口。**[已由源码确认：设计文档]**
- 影响：中。三类风险——① 幻觉（编造 event_id / 伪造证据链）；② 成本与外网依赖（断网、限流、计费失控）；③ 数据外传（RSSI 时序与场地信息出域）。
- 缓解：① 引用 ID 白名单校验 + 字段黑名单（坐标/轨迹/频谱字段不允许出现在 schema）+ 专项单测；② 每日 token 预算 + 并发 1 + 熔断，禁用态必须零功能回退；③ 出域前脱敏（不含密钥/精确位置/飞手姓名，用化名映射）、审计表只存 hash 不存正文。**[需要实机验证：本地模型可行性与真实 provider 联调均未执行]**

## R11–R26：多场地定案、②a 裁定与各阶段实测新增（索引）

2026-10-28 需求定调（多场地 / 场地内多中继多节点 / 不做云端 / 每场地一套实例 + 局域网只读汇聚）后新增的十条风险，加上 2026-10-29 方式②形态裁定（选 ②a PL011 直连）新引入的 R21，再加上 **S4/S5/S6 实现阶段实测撞出来的五条**（R22/R23/R24/R25/R26），共十六条；**详细缓解措施只写在 [`../rf-track/RF_Track_落地实施方案与计划.md` §9](../rf-track/RF_Track_落地实施方案与计划.md) 一处**，本节只做索引以免双写漂移：

| ID | 一句话 | 等级变化 |
|---|---|---|
| R11 | SD 卡写磨损（SQLite 在 Pi 的 SD 上） | 多场地后**中→高** |
| R12 | serve.mjs 与 FastAPI 双网关功能重叠、语义漂移 | 中 |
| R13 | Pi 上已验证但未提交的改动 | **已消解→低**（2026-10-29：`7bec675` 已入库 1253/38；残余是 web 与 firmware 捆在同一提交、不可分拆回滚） |
| R14 | 多 uvicorn worker 重复订阅端点触发 busy 抢占 | 低→中 |
| R15 | 容量边界 | **定案后范围收窄**（单实例只管一个场地） |

| R17 | 场地内多位置间数据串 | 风险位置转移（隔离测试覆盖面改变）；**S6 后六面里五面有断言**（设置/布局/保留/事件/按场地 WS 扇出），只剩告警那一面归 S8 |

| R22 | **版本号与结构事实分离**：`alembic_version` 写着 head 而库里少一张表，且 alembic 不会重跑已应用的修订号 | 中，**S4 实测发现**；对策是自检 + `schema_gaps` 如实报，**只报不修** |
| R23 | **"清同组旧值再置新"的 flush 顺序**：同批 ORM UPDATE 按主键排序，而部分唯一索引按语句即时校验 | 中，**S5 实测发现**；判据成立与否取决于主键分布而非代码路径，所以单测只测一个方向就会长期假绿 |
| R24 | **跨语言边界的 JSON 形状漂移**：前端读一个服务端不存在的字段、且自己的单测夹具也造了那个形状 | 中，**S5 实测发现**；FastAPI + Vue CDN 无构建没有共享 schema，这类缺陷只表现为"页面少一行信息"，不会报错 |
| R25 | **夹具的"值的定义域"没有判据**：合成帧里的 `channel.id=8` 在线上根本不是合法档位（0 基、`PROFILE_MAX_CHANNELS 8`），而 CRC 正确、两份解析器都照收、对拍 37 条全绿，于是被一路照抄进录制→清单→页面 | 中，**S6 实测发现**；是 R24 的近亲但更隐蔽（漂的是取值范围而不是形状），整条链上**只有页面**拿合法域要求过数据，所以只有最慢那一层抓到它 |
| R26 | **门槛自己会假绿**：冒烟的等待条件写成"数行数 / 数个数 / 等中间态"时不产生失败，只产生"通过"，而这些数字会被后续阶段当成既成事实引用 | 中，**S6 实测发现**（三条红全是脚本判据写错，不是页面缺陷）；对策是"等到最终显示位置 + 点名每一个消费者 + 断言终值前先等放完" |

其中 R19、R20 是 2026-10-28 定案**新引入**的（不是既有风险的升级）：前者要求把滞后显式化（`last_sync_at`/`lag_s` 常驻、超阈值置灰为「陈旧」、aggregator 角色不提供 `/ws/bridge`）；后者要求版本可比对——`/api/health` 与 `/api/aggregate/*` 都回 `schema_version` + `app_version`，汇聚侧把"版本不匹配"单列一种失败原因（借本项目「包内固件清单必落后一代」的同类教训）。R21 是 2026-10-29 选定②a（桥接期间停 RotorHazard）之后才存在的：正常关桥已实测会 `resumeRh`，异常路径（标签被杀 / serve.mjs 崩溃 / Pi 重启）没有任何实测，所以它同时是风险**和**一条真机待验项（见 [`topology-and-access-methods.md` §7 第 7 条](topology-and-access-methods.md)）。
R22/R23/R24/R25/R26 与前十二条**来源不同**：它们不是需求定调或硬件裁定推出来的，而是**实现阶段实测撞出来的**——R22 在 S4（迁移场景 2 会把缺表的库 stamp 成"最新"），R23/R24 在 S5（页面第一次真调 `/api/layouts` 与 `/api/nodes`），R25/R26 在 S6（页面第一次真吃帧数据）。共同点是**都不会以报错的方式出现**：R22 是几周后某个页面 500 而健康检查说正常，R23 是"切回原布局切不动"这一条只在主键分布对上时才发生，R24 是"页面上少了一行上限"这种看起来像排版问题的东西，R25 是"矩阵少画一行"而三份期望值（夹具、录制、清单）一致地错，R26 更是**连红都没有**——判据写错的那几条本来就打算一直绿。补记这三条时也修正一处本文件自己的疏漏：**R22 在 S4 就写进了方案 §9，但当时没进这张索引**——一张需要人工记得同步的清单，漏一条是常态而不是意外（S6 这次两边同一轮补齐，正文在前、索引在后，且顺手把 R17 那一行的"六面里有几面已落地"跟着实况更新了一次——这张表里**任何一句"待补"都该在实现阶段结束的那一轮被重读**，否则它就变成第二条 R22）。

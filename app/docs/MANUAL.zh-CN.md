# Widscan58 安卓应用操作手册

本手册是**参考口径**：按功能逐项列出界面元素、控件取值和它对应的固件命令，供查阅。
第一次上手的图文教程不在这里，而在应用内：**⋯ → 使用帮助**（源文件
`mobile/src/main/assets/help/index.html`，随 APK 一起打包，离线可读）。

- 适用版本：`0.9`（versionCode 9）
- 运行要求：Android 8.0（API 26）及以上，手机支持 USB Host / OTG
- 板卡：ESP32-C5 跑 widscan58 固件；原生 USB 是 Espressif USB-Serial/JTAG，
  VID `0x303A` / PID `0x1001`，枚举为 CDC-ACM
- 应用**不烧录固件**。清单里只有两条权限，`INTERNET` 与 `REQUEST_INSTALL_PACKAGES`，
  两者都只为「⋯ → 关于」的检查更新与应用内升级服务（见 9.10、16）；扫描本身不联网

相关文档：[README.zh-CN.md](../README.zh-CN.md)（构建与安装）、应用内教程（图文上手）。

## 1 安装与首次连接

### 1.1 接线

板卡 USB-C 口 → 数据线 → 手机 USB-C 口。板卡由手机供电（描述符里 `max_power` 为
500 mA），不需要另外接电源。若手机只有 USB-A 口，用 OTG 转接头，但这类转接头通常
不能同时供电。

### 1.2 打开应用

应用注册了 `USB_DEVICE_ATTACHED` 过滤器（`res/xml/device_filter.xml` 只按 VID 匹配），
所以插上板卡可能自己就起来了。**没有"连接"按钮**：应用启动后自己查找 VID
`0x303A` 的设备并打开。

首次插上会弹 USB 权限框。拒绝后状态行显示 `打开失败：permission denied for …`，
重新拔插一次即可再问。

### 1.3 连接后的握手

链路打开后应用先发 `PROTOCOL MONITOR`，然后按顺序执行：

| 顺序 | 发出的命令 | 目的 |
|---|---|---|
| 1 | `SCAN STOP` | 先停掉板卡上正在跑的扫描，免得边改参数边出帧 |
| 2 | `CHANNELS …`、`MODE …`、`GAIN …`、`ENABLE …` | 把**手机本地记住的**设备设置写回板卡 |
| 3 | `SPEC 4 256 40000000 MAX` | 定下全景/瀑布的取样方式 |
| 4 | `PROFILE?` `STATUS?` `SPURS?` | 读回档案、状态与杂散表 |
| 5 | `SCAN START` `INFO` | 开始扫描，读固件版本 |

> **注意**：第 2 步会用手机的本地偏好**覆盖板卡上的设置**。在网页端改完参数再拔到手机上，
> 手机会把它自己记的那套写回去。要在手机上改，就改完之后再看，别指望板卡的掉电设置。

### 1.4 断开与恢复

- 应用离开前台：`onPause` 会关掉串口，状态行显示 `已暂停`；回到前台自动重新找设备、
  重开、重握手。四种情况会走到这里——退到后台、打开 `使用帮助`（独立窗口，见 9.9）、
  打开 `关于`（独立窗口，见 9.10）、在 `常规设置` 里换语言（会重建界面，见 9.1）。
- 拔线或板卡复位：状态行显示 `已断开：<原因>`。
- 链路在但 3 秒没有新数据：看门狗报 `无数据，重新进入监听模式`。阈值见
  `Widscan58Activity` 的 `NO_DATA_MS = 3000`，检查周期 1 秒。

## 2 界面结构

竖屏，自上而下：

| 区域 | 内容 |
|---|---|
| 状态行 | 档案名、旋转速率、跳频数、增益、链路占用率，或一条提示 |
| 控件条 | 波段 `R A B E F L` · 检波 `峰值 均值` · `参数` · `⋯` |
| 全景图 | 纵轴 dBFS、横轴 MHz 的频谱，叠加信道标记 |
| 瀑布 | 全景下方，一行 = 一次频谱取样 |
| 频道卡网格 | 2×4 共 8 张，每张一个计划信道 |
| 底部条 | `开始/停止` · 增益滑条（数值 + 条） · `峰值保持` |

没有链路时网格与瀑布都不画，只留空态与提示。

## 3 状态行

| 字段 | 来源 | 含义 |
|---|---|---|
| `模拟设备 · c5-race` | `PROFILE` 回复 | 当前档案名；没读到之前显示"连接中…" |
| `1 圈/秒` | 遥测帧 | 整张计划跑完一遍的速度 |
| `8 次跳频` | `STATUS` 的 hops | 计划里的信道数，最多 8 |
| `增益 45` | `STATUS` 的 gain | 接收增益，**PHY 表序号，不是 dB** |
| `链路 12%` | `TELEMETRY` 的 `link_fill_pm` | 板卡发送队列占用率（千分比换算成百分比）。**越低越好**，0% 表示数据一产生就被取走；持续升高说明 USB 带宽或手机侧来不及收，画面会掉帧 |

`链路 0%` 不是断链，是健康状态。

## 4 全景图与瀑布

- 纵轴范围由 `显示 dB 范围`（下限/上限）决定，或 **⋯ → 自动缩放** 按当前画面重算。
- 每个计划信道画一条竖向色带，配 4 条标记线：
  - 虚线框：信道的搜索窗口
  - `V`：最净底噪位置
  - 中心线、占用带宽（OBW）上下沿
- 曲线叠三条：实时、峰值保持（`峰值保持` 按钮开）、平均（`均值` 检波）。
- 瀑布每一行对应一次频谱取样，即每 `specEvery` 跳一行；这是与网页端一致的语义，
  不是 bug。横轴左端是过去，右端是现在。
- 点全景上的任意位置会选中最近的信道。

## 5 频道卡片

每张卡显示：

| 行 | 字段 | 来源 |
|---|---|---|
| 标题 | 信道名 + 频率 MHz | `CHANNELS` 计划 |
| 大字 | 电平 dBFS | `rssi` |
| 色条 | 电平相对显示范围 | — |
| 明细 | 信噪比 / 底噪 / 最净底噪 / 中心 / 占用带宽 | `snr` `floor` `clearFloor` `centroidOffHz` `obwLoHz`~`obwHiHz` |
| 徽标 | 见下表 | `flags` |
| 迷你曲线 | 该信道的电平历史 | `History` |

徽标（`ChannelTile.kt`）：

| 徽标 | 触发 | 说明 |
|---|---|---|
| `过期` | 距上次更新 > 1 秒 | 该信道没有新读数 |
| `有信号` | `ChannelFlag.SIGNAL`（位 1） | 固件判定窗口内有载波 |
| `削波` | `SATURATED`（位 2） | ADC 饱和，往下降增益 |
| `杂散` | `SPUR` | 峰值落在杂散表上 |
| `杂散已抑制` | `MASKED`（位 4） | 搜索窗里剔除了 DC/杂散格 |
| `滤波边缘` | `EDGE`（位 8） | 信道太靠近模拟滤波边缘 |

> `有信号` 和 `杂散已抑制` 是否出现，取决于固件的 `METRICS` 模式。`RSSI` / `SNR`
> 两种精简模式下固件不报这些位，卡片就不会有"有信号"徽标——这是固件行为，不是应用漏画。

点卡片进入**频道细节**：单信道的偏移-电平图，含标称、最忙、中心、电平、平滑、信噪比、
底噪、峰值、占用带宽，`上一个频道`/`下一个频道` 可连续翻。

## 6 控件条与底部条

| 控件 | 作用 |
|---|---|
| `R A B E F L` | 一键把整个波段填成 8 信道计划（见第 8 节） |
| `峰值` / `均值` | 频谱检波方式，对应 `SPEC … MAX` / `MEAN` |
| `参数` | 打开扫描参数表（第 7 节） |
| `⋯` | 其余视图（第 9 节） |
| `开始` / `停止` | `SCAN START` / `SCAN STOP`，随后补一条 `STATUS?` |
| 增益滑条 | `GAIN MANUAL n`，上限取板卡上报的 `gainMax`（无上报时按 PHY 表深 82） |
| `峰值保持` | 只在显示层保留历史最大值，不影响测量 |

没有链路时 `开始`、增益滑条、`参数` 都是禁用的。**这个主题下禁用态几乎不变灰**，
点了没反应容易误以为卡住——看状态行是否写着"请用 USB-C 连接"。

## 7 扫描参数逐项

原则：**一个控件对应一条固件命令**，改完都会重读 `STATUS?`，显示的是板卡的真实状态。
取值范围与命令拼装都在 `core/…/DeviceCommands.kt`。

| 控件 | 命令 | 取值 | 未改时的值 | 说明 |
|---|---|---|---|---|
| 频道计划 → 编辑 | `CHANNELS …` | 最多 8 个已知信道名 | 档案决定 | 见第 8 节 |
| 扫描频道 全选/全不选 | `ENABLE <mask>` | `mask & 0xff`，每位一个信道 | 计划内全开 | 计划内临时启停个别信道 |
| LO 模式 | `MODE GROUP` / `MODE SINGLE` | 二选一 | 手机记住的，一般 `GROUP` | 单频点用于把某个频率盯死 |
| 增益模式 | `GAIN MANUAL n` / `GAIN HARDWARE` | MANUAL 0…`gainMax`(82) | 手机记住的，默认手动 | 硬件 AGC 交给前端跟 |
| RX 增益 | 同上 `n` | PHY 表**序号**，非 dB | 手机记住的，滑条以板卡上报为准 | 出现`削波`就降档 |
| 模拟滤波码 | `FILTER AUTO` / `FILTER n` | `n` = 0…63，−1 视为 AUTO | 手机侧自动；`c5-race` 档案本身是 0 | 前端模拟滤波器档位 |
| FFT 点数 | `FFT n` | 64/128/256/512/1024/2048（就近取档） | 档案 1024 | 决定频率分辨率 |
| 采样点数 | `CAPN n` | 256/512/1024/2048/4096/8192/16380 | 档案 4096 | 每次采集的原始样本数 |
| 平均段数 | `SEGMENTS n` | 1…64 | 档案 4 | 越大越平滑越迟钝 |
| 通道测量项 | `METRICS FULL` / `RSSI` / `SNR` | 三选一 | 手机记住的，默认 `FULL` | 精简模式会少报徽标与派生量 |
| 窗口 ± kHz | `WIN <rssi_hz> <search_hz>` | 各 10 000…20 000 000 Hz | 档案 5 000 000 / 12 000 000 | 界面上填 kHz，发出去是 Hz |
| 平滑系数 α | `EMA <千分比> <千分比>` | 0.001…1.0，按 ×1000 发送 | 板卡上报（截图里 0.250 / 0.020） | RSSI 快、底噪慢，底噪慢是为了留住"最净底噪" |
| 显示频谱 | `SPEC <every> <bins> <span_hz> MAX\|MEAN` | every 0…255；bins 64/128/256/512/1024；span 100 000…40 000 000 Hz | 连接时应用强制 `4 256 40000000 MAX` | 每几跳画一行、横向格数、覆盖宽度 |
| 校准模式 | `RECALMODE CACHE\|ONCE\|EVERY` | 三选一 | 板卡上报 | 本底校准表怎么复用 |
| 立即校准 | `RECAL` | — | — | 换天线/加衰减后点一次 |
| 调谐后稳定 µs | `SETTLE n` | 0…20 000 µs | 板卡上报（截图里 100） | PLL 锁定后额外等多久再采 |
| 跳过调谐（调试） | `TUNESKIP <mask&7>` | 1=仅 PLL，2=关 RX 通道，4=跳过增益 | 板卡上报（正常全关） | 位开关，会改变读数含义 |
| 频谱方向 | `CONJ 0\|1` | 0/1 | 档案里 `c5-race` 为开 | I/Q 共轭，等价左右翻转 |
| IQ 校正 | `IQCORR 0\|1` | 0/1 | 板卡上报 | 关掉后中心会出现假的直流尖峰 |
| 显示 dB 范围 | 不下发 | — | 手机记住的 | 纯显示，也可用 ⋯ → 自动缩放 |
| 重启设备 | `REBOOT` | — | — | 板卡复位，链路会断一下 |
| 烧录模式 | `BOOTLOADER` | — | — | 进 ROM 下载口，**扫描一直停到重新烧录或按复位** |

## 8 频道计划与波段表

`⋯` 之外，波段芯片和 `参数 → 频道计划 → 编辑` 都能改计划。编辑器规则：**最多 8 个信道**；
点波段名一次选中该波段全部 8 个。

| 波段 | 名称 | 1…8 频点（MHz） |
|---|---|---|
| R | Raceband | 5658 5695 5732 5769 5806 5843 5880 5917 |
| A | Boscam A | 5865 5845 5825 5805 5785 5765 5745 5725 |
| B | Boscam B | 5733 5752 5771 5790 5809 5828 5847 5866 |
| E | Boscam E | 5705 5685 5665 5645 5885 5905 5925 5945 |
| F | Fatshark | 5740 5760 5780 5800 5820 5840 5860 5880 |
| L | Low band | 5362 5399 5436 5473 5510 5547 5584 5621 |

规范化规则（`Bands.normalize`）：去重 → 只留上表已知名字 → 截到 8 个 → 按频率升序
（同频保持图表顺序）。所以卡片上的 `B1…B8` 编号是按频率排下来的，不一定等于点选顺序。

发出的命令形如 `CHANNELS R1=5658 R2=5695 …`。

## 9 ⋯ 菜单：各视图

菜单按这个顺序排：`常规设置`、`自动缩放`、`RSSI 历史`、`扫描器遥测`、`协议控制台`、
`GPIO 配置`、`录制与导出`、`计圈（RotorHazard）`、`功率计`、`原始 I/Q 快照`、`使用帮助`、`关于`。

除 `使用帮助` 与 `关于` 是独立页面外，其余都是主界面上的浮层，右下角 `关闭` 或返回键退出。
这两个因为是新窗口，会让主界面走一次 `onPause`（见 1.4）。
`计圈` 与 `功率计` 会改写扫描设置，各自单列在第 11、12 节。

### 9.1 常规设置

目前只有一项：`语言` → `中文` / `English` / `跟随系统`，装机默认中文。

- 选语言只改界面文案，不动板卡、不发命令；中英文是同一套布局。
- 切换会**重建界面**，等价于退到后台再回来：串口先关一次再重握手（见 1.4），
  正在跑的扫描会短暂中断，之后自动接上。
- 在**计圈模式中途**换语言：不崩、进程不变，但计圈会话随界面一起结束、圈数清零，
  要重新进 `⋯ → 计圈`。这是接受的行为。
- `跟随系统` 交给 Android 按应用语言设置决定；手机系统是英文时首屏就是英文。
- 这一项**不影响应用内教程**：`使用帮助` 那一页目前只有中文，页首有一行说明。

### 9.2 自动缩放

按当前画面重算纵轴上下限，一次性的，不改变 `显示 dB 范围` 的持久值。

### 9.3 RSSI 历史

八条曲线对应八个信道，横轴是"多少秒前"，右侧 0 是现在。

| 控件 | 取值 |
|---|---|
| 回看时长 | 10 / 30 / 60 / 120 秒 |
| 平滑 / 原始 | 画指数平滑线还是逐点原始线 |
| 拖动 | 立起指针读该时刻各信道电平；`取消指针` 清掉 |

曲线左端空一截是正常的：那个时间点还没有采样。

### 9.4 扫描器遥测

| 指标 | 含义 |
|---|---|
| 旋转速率 | 整张计划每秒跑几圈 |
| 每跳耗时 | 一跳的总时长，下方有分解图（调谐 / 采集 / DSP），拖动看单跳 |
| 设备发送队列 | 板卡输出队列占用（千分比），持续高 = 链路来不及送 |
| 链路吞吐 | 手机侧收到的字节速率，另有"最近 10 秒丢弃 / 累计 MiB" |
| 错误 | 采集错误与重同步字节数 |
| 空闲堆 | 板卡剩余内存，另有内部 RAM |

每跳耗时分解图横轴是毫秒、每一跳；`最近 N 跳` 可切换窗口。

### 9.5 协议控制台

链路两端的原始记录，`> ` 是发出、`< ` 是收到（`LogDir` 的箭头）。支持手输命令，
快捷按钮：`INFO`、`STATUS?`、`TIMING?`、`SPURS?`、`GAIN?`。
回放打开时控制台是只读的：`回放是只读的：不能再发送命令`。

### 9.6 GPIO 配置

板卡上电时各输出引脚的状态。`-` 未使用、`L` 拉低、`H` 拉高、`x` 被 flash/USB 占用。
`GPIO <pin> <LOW|HIGH|NONE>` 只是**当下驱动**，要点 `保存` 才发 `GPIO SAVE` 成为开机设置；
有未保存改动时 `保存`/`还原` 才可点。

### 9.7 录制与导出

| 动作 | 说明 |
|---|---|
| 开始/停止录制 | 录的是**设备字节流**加每条到达时间，见 10.1 |
| 保存 `.widscan58` | 通过系统文件选择器写盘，成功提示 `已保存 <名>（<大小>）` |
| 打开 `.widscan58` | 回放，只读；空文件提示 `没有可回放的记录`，放完提示 `回放结束` |
| 导出频道 CSV | 见 10.2 |
| 导出频谱 CSV | 见 10.3 |

录制上限 32 MiB 载荷，超过就停止接收并标记"尾部缺失"。

### 9.8 原始 I/Q 快照

一次采集、三张图。数值全在手机上算，板卡只发样本。

| 控件 | 取值 / 行为 |
|---|---|
| `LO kHz` | 本振（千赫兹）。打开时按"当前选中通道 → 计划里同号通道 → 计划第一个通道"填初值，所以不会是空的 |
| `用所选通道 LO` | 把上面的顺序再走一遍回填输入框 |
| `采集` | 发 `RAWIQ <lo_khz> <samples>` |
| `样本数` | 1024 / 4096 / 8192 / 16380，默认 8192 |

- 超过板卡上报上限（`STATUS?` 回包里的 `rawiq_max`）的档位**变暗且点不了**；没读到这个字段时
  四档都可点。模拟源恒报 16380，所以这条禁用路径只有接真板才看得到。
- 三张图自上而下：**星座图**（I/Q 散点，量程跟峰值走 `max(8, 峰值×1.15)`，
  不是固定 ±128）、**前 400 个样本的 I / Q 时域**、**整次采集平均后的 1024 点 Hann FFT**
  （纵轴每 bin dBFS，横轴按这次采集自己的跨度铺成绝对兆赫兹）。
- LO 正好打在信道上，星座是一个点团；打在信道之间（如 5720 MHz）是标准圆环。
- 信息行给的是 `LO MHz · MS/s · 样本数 · 每计数对应的 10 bit ADC 计数 · 直流 (I,Q) · RMS · 峰值/512`；
  这次采集的头部共轭位为 1（样本做过 I/Q 共轭，等价频谱左右翻转）时，行末追加 `已共轭`。
- FFT 按**快照**算一次并缓存，不随仪器重绘每帧重算。

### 9.9 使用帮助

应用内的图文教程，随 APK 打包在 `mobile/src/main/assets/help/index.html`，
打开的是本机的一个页面：**不联网**，只加载 APK 里的那一个文件。
它是独立 Activity，所以离开主界面会走一次 `onPause`（见 1.4），按返回键回去后自动重连。
图可以点开全屏查看。目前只有中文。

### 9.10 关于与升级

同样是独立 Activity（`AboutActivity`），打开时串口按 1.4 的规则关闭一次。

| 元素 | 内容 / 行为 |
|---|---|
| 版本 | `BuildConfig.VERSION_NAME`，即装机版本 |
| 构建号 | `BuildConfig.VERSION_CODE` |
| 发布仓库 | `BuildConfig.RELEASE_REPO` = `onebody/widscan58` |
| 许可 | `GPL-3.0-or-later` |
| 检查更新 | `GET https://api.github.com/repos/onebody/widscan58/releases?per_page=20`，只认 `app-v` 开头的标签，取其中带 `.apk` 附件的最新一条 |
| 安装 x.y | 下载该附件 → 按附件公开的 `sha256` 校验 → 交给系统 `PackageInstaller` 会话 |
| 打开发布页 | `ACTION_VIEW` 打开 `https://github.com/onebody/widscan58/releases`，应用内路径走不通时的后备 |
| 去设置 | `ACTION_MANAGE_UNKNOWN_APP_SOURCES`，直接落在本应用的「允许安装未知应用」开关上 |

- 网络只在按「检查更新」或「安装」时发生，没有后台任务、没有开机自启。
- 校验和是硬门槛：不匹配即 `abandon()` 会话并提示「校验和不匹配，安装包已丢弃」，不会拉起安装器。
- 发布附件没带 `digest` 时提示「未公开校验和」，装不装由你决定。
- 安装器的答复走广播（`com.onebody.widscan58.INSTALL_STATUS`，仅本应用可收）：
  本应用正是被替换的那个，未必还有窗口可以回报。承载这个答复的 `PendingIntent`
  **必须可变**——安装器是靠「填回」这条 Intent 送状态的，`FLAG_IMMUTABLE` 会让它收到一条空 Intent。
- `STATUS_PENDING_USER_ACTION` 带回来的 `Intent.EXTRA_INTENT` 由应用 `startActivity` 出去，
  就是用户点「安装」的那个系统弹窗。
- 拨动「允许安装未知应用」的瞬间系统会杀掉本应用进程（`REQUEST_INSTALL_PACKAGES changed.`），
  所以授权后回到应用是重新打开的页面，需要再按一次「检查更新」。

## 10 数据文件格式

### 10.1 `.widscan58`

与网页端录制格式一致，小端：

```
u32 相对开录的毫秒 | u32 本条长度 | 原始字节
```

开头会先写入 `PROFILE?` / `STATUS?` 等前导行的字节，所以回放不需要重发命令就能重建界面。
单条记录超过 1 MiB 视为文件损坏而不是正常帧。

### 10.2 频道 CSV（`channelsCsv`）

一行一个计划信道，取该信道**最后一次**读数：

```
id,name,freq_khz,enabled,flags,rssi_dbfs,rssi_ema_dbfs,noise_dbfs,snr_db,
clear_floor_dbfs,peak_dbfs,peak_offset_hz,centroid_offset_hz,obw_lo_hz,obw_hi_hz,age_s
```

`age_s` 是距上次更新的秒数；从没测过的信道留空。

### 10.3 频谱 CSV（`spectrumCsv`）

```
freq_khz,live_dbfs,max_hold_dbfs,avg_dbfs,noise_floor_dbfs
```

按全景当前跨度均匀取 **1000** 列（`SPECTRUM_COLUMNS`），每列取该格的中点频率。
无值的 dB 读数是**空字段**，不是 0 也不是 NaN。

## 11 计圈（RotorHazard）模式

把板卡当成无人机计时系统的接收机。入口 `⋯ → 计圈`。

- **只有真板卡可以**：模拟设备不能计圈，提示 `模拟设备不能计圈…`。
- 进入时发 `PROTOCOL RH`，把串口交给 RH 轮询器；退出时发 `PROTOCOL MONITOR` 交还扫描。
- 界面分四块：**座位**（8 个接收机位，每位的当前电平与判圈门限）、**电平**（各座实时/
  门限线）、**事件**（过圈流水）、**接收机**（远端参数）。
- 座位芯片在该座没有通道时禁用。`最快` 徽标只在"最快圈"规则打开时启用。
- 换界面语言会结束这次计圈（见 9.1），圈数清零。
- 语音报圈：`语音` 开关 + 音量 / 语速 / 音高三条滑条。语音走系统 TTS，清单里已经加了
  `TTS_SERVICE` 的 `<queries>`，否则 Android 11+ 的包可见性会让引擎"消失"、报圈静默失败。

## 12 功率计模式

入口 `⋯ → 功率计`。把接收电平经衰减器折算成发射功率。

进入时应用会**改写扫描设置**：

```
MODE SINGLE
GAIN MANUAL 0
WIN 15000000 15000000
METRICS FULL
SPEC 0 256 <可用跨度> MAX
```

退出时还原：先还原进入前的监视扫描快照（窗口 + SPEC），拿不到快照时按档案默认
（`c5-race`：`WIN 5000000 12000000` + `SPEC 4 256 40000000 MAX`；`s3-race24`：
`WIN 1410000 3390000` + `SPEC 4 256 11300000 MAX`），并重发 `MODE` 等。
功率计页**自己不改回** `MODE` 和 `GAIN`，所以退出这一步是必须的——中途强杀进程会留下
单频点 + 0 增益的状态，重开应用握手时会纠正。

### 12.1 衰减器表

`Power.kt` 内置的建议表（**必须经衰减器连接 VTX**，ESP 大约能读 −32 dBm 到 −5 dBm）：

| VTX 功率 | dBm | 建议衰减 | 衰减器功率耐受 |
|---|---|---|---|
| 25 mW | +14 | 30 dB | 0.5 W |
| 500 mW | +27 | 40 dB | 1 W |
| 1 W | +30 | 40 dB | 2 W |
| 2 W | +33 | 40 dB | 5 W |

### 12.2 平滑

可选 0 / 0.1 / 0.5 / 1 / 3 秒的时间窗平均。未做校准时页面上会写
`这块板（<板卡名>）没有功率校准：功率计模式需要 ESP32-C5 板卡。`，
读数只作相对比较。另有一行免责说明
`功率值来自单块 C5 的校准，只是近似值。`——这是接收机折算值，不是功率计认证读数。

## 13 协议附录

### 13.1 帧格式

```
0xA5 'R' <type:u8> <version:u8> <len:u16> <payload> <crc32:u32 (zlib)>
```

解析器会重同步：`0xA5` 后面不是 `'R'` 就跳一个字节继续找，重同步字节数计入遥测。
文本行以大写命令词开头（正则 `^[A-Z][A-Z0-9_?]*( |$)`）。

### 13.2 帧类型

| type | 名称 | 用途 |
|---|---|---|
| 1 | `METRICS` | 每跳的完整信道测量（34 字节头 + 26 字节/信道） |
| 2 | `SPECTRUM` | 全景/瀑布的谱数据 |
| 3 | `TELEMETRY` | 旋转速率、队列、吞吐、内存 |
| 4 | `RAWIQ` | 原始 I/Q 分块，末块标志结束一次采集 |
| 5 | `LOG` | 固件日志行（控制台里的 `<` 记录） |
| 6 | `LEVELS` | 精简电平帧（`METRICS RSSI` / `SNR` 模式下） |

### 13.3 电平编码

| 量 | 换算 |
|---|---|
| 电平码（0.25 dB 步进） | `dBFS = code / 4 − 63.75` |
| SNR 码 | `dB = code / 4` |
| 头里的每格底噪 | `dBFS = code / 2 − 127.5` |
| 信道内 `i16` 读数 | 百分 dB：`value / 100` |
| `clearFloor` | `Short.MIN_VALUE` 表示"无值" |

### 13.4 应用会发出的命令

`SCAN START` `SCAN STOP` `CHANNELS` `MODE` `GAIN` `FILTER` `FFT` `CAPN` `SEGMENTS`
`METRICS` `WIN` `EMA` `SPEC` `SETTLE` `RECALMODE` `RECAL` `TUNESKIP` `CONJ` `IQCORR`
`ENABLE` `GPIO` `GPIO SAVE` `RAWIQ <lo_khz> <samples>` `PROFILE?` `STATUS?` `SPURS?`
`GPIO?` `TIMING?` `INFO` `PROTOCOL MONITOR` `PROTOCOL RH` `REBOOT` `BOOTLOADER`。

命令是**串行**的：`CommandRunner` 发一条后等它的回复行（或帧）再发下一条，超时不阻塞
解析线程。

## 14 故障排查

| 现象 / 状态行 | 原因 | 处理 |
|---|---|---|
| `请用 USB-C 连接 Widscan58 板卡。` | 没有链路 | 检查线（很多短线只有电源线芯）、OTG 开关 |
| `打开失败：permission denied for …` | USB 权限被拒 | 拔插一次，弹窗点"允许"，可勾"默认" |
| `… 不是 CDC 串口` | 描述符里没有 CDC 接口 | 用 `MainActivity`（探针）看描述符，确认固件的 USB-Serial/JTAG 开着 |
| `已断开：<原因>` | 链路掉了 | 重新插拔，应用会自动重连 |
| `已暂停` | 应用离开前台：退后台 / 打开 `使用帮助` 或 `关于` / 换语言 | 回主界面自动重连重握手 |
| `无数据，重新进入监听模式` | 链路在但 3 秒无帧 | 板卡可能停在 `SCAN STOP`；重开监听或复位板卡 |
| `链路 0%` | 队列排空很快 | 健康状态，不是故障 |
| 链路占用率持续升高、画面掉帧 | USB 带宽或手机来不及收 | 减小 `SPEC` 格数/跨度，或降 `SEGMENTS` |
| 所有读数钉在 −63.8、SNR 0 | `METRICS` 在 `RSSI`/`SNR` 精简模式 | 想要完整读数就切回 `FULL` |
| 卡片没有"有信号"徽标 | 同上，精简模式固件不报位 | 切 `FULL` |
| 中心一根尖峰 | `IQCORR` 关了 | 打开 IQ 校正 |
| 高侧信号画到低侧 | 频谱方向反了 | 切 `CONJ` |
| 增益滑条拉满仍削波 | 前端饱和 | 加衰减，或降 `RX 增益` |
| 按钮点了没反应 | 无链路时禁用，且禁用态几乎不变灰 | 看状态行 |
| 点 `烧录模式` 后没扫描 | 板卡进 ROM 下载口 | 重新烧录或按复位键 |

## 15 术语表

| 术语 | 在本应用里指什么 |
|---|---|
| LO | 本振频率，即板卡当前调谐到的中心频率 |
| 跳 / hop | 一次"调谐 + 采集 + 计算"，计划里 8 个信道轮着跳 |
| 圈 / rotation | 整张计划跑完一遍 |
| dBFS | 相对满量程的接收电平，负值，越接近 0 越强 |
| RSSI | 窗口内的接收信号强度 |
| SNR | 峰值相对本底信噪比 |
| 底噪 / 最净底噪 | 当前噪声地板 / 观察到的最低地板，用来判"有没有东西" |
| OBW | 占用带宽，固件给的上下沿（kHz 偏移） |
| 中心偏移 | 峰值相对标称频率的偏移（Hz） |
| 检波 | 每格取峰值还是均值 |
| 平滑 α | 指数平滑系数，越大越跟手 |
| 杂散 | 落在杂散表上的假峰 |
| 滤波边缘 | 信道太靠近模拟滤波器的滚降边 |
| CDC / ACM | USB 串口设备类别，应用按它找端口 |
| OTG | 手机当 USB 主机的工作模式 |
| PHY 表序号 | ESP32-C5 接收增益的档位号，不是 dB |

## 16 隐私与权限

- 清单里只有两条 `<uses-permission>`：`INTERNET` 与 `REQUEST_INSTALL_PACKAGES`。
  两条都只为「⋯ → 关于」的检查更新与应用内升级服务（见 9.10）；不定位、不读存储、
  不申请设备标识，也没有其他任何权限。
- 全应用唯一一次向外发的请求是你在关于页按下「检查更新」时那一个 HTTPS GET，
  目标只有 `api.github.com` 上本仓库的发布列表；请求头里带的是应用名和一个
  `widscan58-android` 这样的客户端标识，不带任何用户数据。扫描、遥测、录圈、导出
  全都只走 USB，不碰网络。
- 升级下载的 APK 必须先和发布页公开的 sha256 对上，对不上就地销毁，不会交给安装器；
  只接受 https 下载地址。
- 导出与录制都走系统文件选择器（Storage Access Framework），应用只拿到那一个 URI。
- 内置教程是 APK 里的静态页面（`assets/help/`），用系统 WebView 本地加载，不引用
  任何远程脚本，板子没插、飞行模式下都能打开。
- 许可：GPL-3.0-or-later。
